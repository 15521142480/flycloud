# 后台前端开发规范

## 适用范围

- 本文件适用于 `flycloud-admin-ui`，不直接约束商城移动端或其他前端项目。
- 同时遵守仓库根 `AGENTS.md` 的配置保护、公共代码复用和协作要求；Java 包结构不直接套用到 TypeScript。
- 新增及修改代码必须遵守本规范；历史的 `VO` 类型、`auto` 词条、`@ts-nocheck` 等不能作为继续新增同类写法的依据，也不因此对无关代码做全仓迁移。
- 修改前阅读目标页面、接口、共享类型及相邻组件，沿用 Vue 3、TypeScript、Element Plus、Pinia、Vue Router 和项目已有封装。

## 目录与复用

- `src/views`：业务页面及仅由该页面使用的局部组件。
- `src/api`：按业务模块组织的接口调用，统一使用 `@/config/axios`，不能在页面中重新封装 Axios、手工拼 Token 或硬编码服务地址。
- **`src/entity`：共享业务对象、查询条件、表单及接口请求/响应的 interface。** 按领域文件或目录归类，参考 `src/entity/system.ts` 和 `src/entity/base/base-entity.ts`。
- `src/types`：通用组件、框架扩展及环境声明，不作为业务表单类型的另一个存放地。
- `src/components`：跨页面通用组件；`src/hooks`：可复用的组合逻辑；`src/utils`：纯工具；`src/store`：确需跨页面共享的状态。
- 业务重复代码应收敛到对应公共模块，先找已有实现，不能复制成多个近似组件、工具或 interface；也不要为单次简单逻辑过度抽象。

## Vue 3 与 TypeScript

- 新增组件优先使用 `<script setup lang="ts">` 和 Composition API，组件名、文件名及 `defineOptions` 沿用所属模块习惯并保持路由兼容。
- 使用 `ref`、`reactive`、`computed` 和类型化的 `defineProps`、`defineEmits`；派生状态优先 `computed`，不要用多组 watcher 手动同步同一份状态。
- 组件、公共函数、interface 及业务字段写清中文注释，重要参数、单位、状态和非直观分支不能只靠变量名猜测。
- 避免 `any`、无约束对象和类型强转掩盖契约错误；不新增整页 `@ts-nocheck`、`@ts-ignore` 或大范围关闭 lint 规则。
- 不在模板中堆复杂业务判断；列表用稳定的业务 ID 作 `key`，事件、订阅及定时器在卸载时按需清理。
- `import type` 用于纯类型依赖；格式、别名、样式及导入顺序遵循当前 ESLint、Prettier 和项目现有约定。

## 表单与接口类型

- **每个业务表单必须有明确的 interface，放在 `src/entity` 对应业务模块中，供页面、弹窗和 API 直接导入使用。** 不能在多个 `.vue` 或 API 文件中重复声明同一表单结构。
- 与后端对应的请求、响应类型按职责使用 `XxxBo`、`XxxVo` 等名称，后缀大小写统一；不再新增 `Dto`、`DTO`、`VO` 命名。
- 表单字段、查询条件、必填性、空值、枚举值和返回类型以实际后端 `Bo`、`Vo` 为准，不能照搬芋道原字段后让后端默默忽略。
- 页面模型通过 `ref<XxxBo>`、`reactive<XxxBo>` 等明确约束。请求和响应结构确实不同时分别建类型；仅用于 UI 的临时字段不得无筛选提交给后端。
- API 函数显式标明入参和返回类型，复用 `BaseEntity`、`PageParam`、`PageResult<T>` 等适用的共享定义；使用前核对实际契约，不能为了复用而伪造字段。
- 分页请求使用 `pageNum`、`pageSize`，响应读取 `list`、`total` 等实际字段；修改公共分页类型时评估所有调用方，不能引入另一套 `pageNo`、`records` 契约。
- 使用 `el-form` 的 model、rules 和字段 `prop` 保持一致，提交前校验，打开新增/编辑时正确初始化，关闭后避免遗留上次校验或数据。
- 查询、清空、重置及分页联动必须可用；聚合搜索显式映射合法查询字段，禁止发出空字符串参数名或只改界面而未携带查询值。

## ID 与数值

- **后端通过 `@JsonLongId` 返回的 ID，前端统一按 `string` 使用。** 主键、外键、父 ID、路由参数、树节点值、选中值及 ID 数组都要保持一致。
- 禁止对 ID 使用 `Number`、`parseInt`、一元 `+`、数值排序或 `v-model.number`；不能把 19 位 ID 先转 number 再转回 string，精度丢失不可恢复。
- 对比、`Map`/`Set`、`includes`、查找及组件 value-key 使用同一种 ID 类型。历史安全的小整数兼容可在数据入口规范为字符串，不得靠宽松相等到处兜底。
- 数量、金额、排序、状态和分页参数仍是对应的数值类型；不要因为 ID 规则把所有数字都改成字符串。
- 金额展示复用已有单位转换和格式化函数；初始、空值及异常响应有明确处理，不能渲染 `NaN` 或将金额单位重复转换。
- 业务状态复用现有字典、枚举或公共常量，含义与后端一致；待发货、待收货等不同状态不能仅为了界面方便混为一个条件。

## 国际化

- **新增或修改的界面文案同步维护 `src/locales/en.ts`、`src/locales/zh-CN.ts`、`src/locales/zh-TW.ts`。** 三份文件的 key 路径、层级和插值参数必须一致。
- 根据所属业务模块归类，例如 `system.user.account`、`system.dept.name`；跨模块的通用操作才复用 `common.save`、`common.cancel` 等公共词条。
- 已有模块下继续扩展，确无归属时建立语义明确的业务模块；**不得把所有文案塞进文件第一个对象、`common` 或一个万能大对象。**
- key 使用有含义的英文 lowerCamelCase；不使用中文 key、拼音、数字序号、随机串或 hash，如 `k7cd8969b`。
- 不再新增 `src/locales/auto`、`src/locales/extra` 式自动或零散词条及对应引用；历史引用在本次相关范围内迁移，不删除仍被其他页面使用的历史词条。
- 标签、标题、按钮、placeholder、校验提示、确认弹窗、空态、错误提示和 tooltip 均使用项目 `useI18n`/`t`，不在模板或脚本中硬编码可翻译文案。
- 变量通过 `{name}`、`{count}` 等插值表达，不拼接翻译片段；切换语言后，依赖文案的表单规则、表头等也应能更新。
- 后端返回的业务内容无需伪装成翻译 key；本地枚举、静态状态显示和前端生成的提示仍须国际化，不能只补中文或用中文充当英文翻译。

## 请求、loading 与错误处理

- 请求及业务错误处理沿用公共 Axios 拦截器，确认它返回的是已解包数据还是原始响应；不能重复解包，或因 HTTP 200 就认定业务成功。
- **loading 只覆盖等待对应接口的区域。** 首页待办请求仅影响右侧待办数量/列表，不能遮住左侧静态欢迎信息或整个首行。
- 按查询、详情、提交等职责分开管理 loading；请求开始设置，使用 `try/finally` 复位，异常时也必须恢复可操作状态。
- 提交期间禁用重复操作；失败时保留用户输入并正确提示，不关闭表单、不跳转、不显示成功。公共拦截器已提示的错误不要再重复弹窗。
- 区分加载中、空数据、请求失败和无权限，不能把失败伪装为空列表；静态信息不应依赖无关请求成功才显示。
- 检查挂载、路由激活及 watcher 的触发关系，避免同一页面无故重复请求；有并发查询时防止旧结果覆盖新条件。
- 页面提供匿名访问时不预取需要登录的用户接口；明确的受保护操作进入现有登录流程，不靠放宽后端权限解决。

## 路由与资源

- 沿用动态菜单和 `src/utils/routerHelper.ts` 的组件解析约定；精确对应组件路径，兼容项目已有的文件/目录入口，不使用模糊 `includes` 匹配“猜”页面。
- 调整路由解析时检查普通页面、目录入口、内嵌聊天入口和独立窗口等已有使用方，避免只修复一个页面而使其他页面空白。
- 文件预览与业务图片复用现有文件 URL 工具，例如上传组件的 `getFilePreviewUrl`；不能假设后端相对存储路径就是浏览器可访问地址。
- 图片列表用数组及 `v-for` 等数据驱动方式渲染；同组预览复用 `ImageViewer`，传完整 `urlList` 和当前 `initialIndex`，左右切换仅在当前分组内。
- 复用现有图标组件及 Element Plus/Iconify 图标，不用无关图标顶替业务含义；确认资源真实存在、路径正确，图片失败时有适当占位。

## 页面与样式

- 保持后台管理页面紧凑、可扫描，沿用项目表格、搜索栏、Dialog、Form、权限指令和主题样式，不另造装饰性页面体系。
- 表单标签、控件宽度、按钮位置遵循相邻页面。搜索框应容纳订单号等实际内容；弹窗、表格和窄屏下文字不能重叠或被无意义裁切。
- 优先复用样式变量和公共类，页面样式合理限定作用域；修改全局样式或公共组件前检查影响面。
- 纯图标按钮提供可翻译的 tooltip 或可访问名称；新增交互同时检查鼠标、键盘焦点及禁用状态，不只做静态外观。

## 验证与交付

- 使用项目现有 pnpm 和脚本，不擅自升级依赖、重建锁文件或全量格式化；保留用户已有改动。
- 按改动范围执行类型检查、定向 lint 和必要构建。可用命令：`pnpm ts:check`、`pnpm exec eslint <修改文件>`、`pnpm exec prettier --check <修改文件>`、`pnpm build:local`。
- `lint:eslint`、`lint:format` 等现有脚本会自动改写大量文件，不能拿来对无关目录做全量“修复”。
- UI 改动验证加载、成功、空态及失败分支；表单验证新增、编辑、重置；涉及 ID、路由和国际化时额外验证类型一致、入口可达及三种语言。
- 本地服务已经运行时复用；确需启动时使用 `pnpm dev` 并说明实际地址，不擅自终止用户已有服务。
- 提交前执行 `git diff --check`，说明验证结果及无法验证的原因；不能把原有类型错误冒充本次修复，也不能声称未执行的浏览器验证已通过。
